# 규정 Q&A (RAG)

신규 임용 공무원의 복무 질문에 규정 원문을 근거로 답합니다. 모델은 근거를 **ID로만** 고릅니다. 조문 표기, 원문, 출처 위치, 시행 정보는 프로그램이 저장된 원문에서 꺼내 보여 줍니다. 규정 기능은 Calendar·Slack·메일을 부르지 않습니다.

## 동작 방식

```
원문 폴더(읽기만) ─ 목록·분류 ─ 파싱(장·절·조·항) ─ 분할 ─ 임베딩(캐시) ─ 색인 버전 ─ CURRENT
                                        (scripts/build_regulation_index.py, CLI로만 구축)
질문 ─ 조건 정리 ─ 시점 확인 ─ 검색(벡터 · 조문 직접 조회 · 참조 조문) ─ 기준 미달이면 모델 없이 보류
     ─ Gemini 구조화 출력(근거 ID만) ─ 결정적 검증 ─ 실패하면 1회 재생성 ─ 또 실패하면 원문 카드만 + 보류
```

1. **조건 정리**: 사용자가 말한 대상(시간선택제·임기제·임신 중 등), 재직기간, 시점만 최근 5턴까지 기억합니다. 이전 답변은 조건으로도 근거로도 쓰지 않습니다. 화면에 "적용 중인 조건"과 지우기 버튼이 있습니다.
2. **시점**: 시점을 말하지 않으면 색인된 현행 버전 기준으로 답하고, 그 시행일을 함께 보여 줍니다. "작년 기준", "개정 전"이나 색인보다 이른 연도를 물으면 모델을 부르지 않고 `source_unavailable`로 답합니다.
3. **검색**: 기본은 질문 임베딩과 청크 벡터의 코사인 유사도 상위 6개입니다(NumPy 벡터 검색).
   - 질문에 법령명과 "제n조"가 있으면 그 조문을 맨 위에 둡니다.
   - 상위 근거가 가리키는 조문은 "참조 조문"으로 더합니다.
   - 임베딩 호출이 실패하면 BM25(kiwipiepy 형태소, "제15조의2"는 한 토큰)로 바꾸고 "키워드 검색만 사용"을 표시합니다.
   - 작은 용어집(연차→연가 등)은 BM25 검색어에만 씁니다.
4. **보류 기준**: 최고 코사인이 `RAG_MIN_SCORE`(0.705)보다 낮으면 모델을 부르지 않고 `escalation_required`로 끝냅니다. 점수는 정확도나 신뢰도처럼 보여 주지 않습니다.
5. **생성**: `generate_structured`로 답변 계약(`rag/models.py`의 ModelAnswer)을 받습니다. 시스템 프롬프트는 `src/onboarding_agent/rag/prompts/qa_system.md`입니다. 모델에게는 질문, 정리된 조건, 검색된 청크의 ID·문서명·조문 표기·원문만 보냅니다. 키·명단·회의 기록은 보내지 않습니다.
6. **보류 기록**: `escalation_required`이면 문의 초안(질문, 조건, 후보 청크 ID, 사유)을 `data/regulations/pending_escalations.jsonl`(git 제외)에 남기고, 화면에 "담당자 확인이 필요합니다. 아직 전달되지 않았습니다"를 보여 줍니다. 아무 데도 보내지 않습니다.
7. **도구 모드**(화면 토글): Gemini function calling 루프입니다.
   - 읽기 도구 `search_regulations`, `get_article`, `get_chunk`와 종료 도구 `submit_answer`, `request_clarification`, `escalate`만 줍니다. Calendar·Slack·파일 쓰기·SQL 도구는 없습니다.
   - 최대 `RAG_MAX_AGENT_STEPS`(4)단계이고, 같은 검증을 거칩니다. 재생성은 하지 않습니다.
   - 호출 기록(도구 이름·인자·돌려준 청크 ID, 비밀값 없음)은 `data/regulations/logs/tool_mode.jsonl`에 남습니다.

## 자료와 제외 이유

자료 목록 원본은 `data/regulations/inventory.json`(메타데이터만)입니다.

| 자료 | 분류 | 외부 전송 | 색인 |
|---|---|---|---|
| 국가공무원 복무규정 PDF(대통령령 제36728호, 14쪽) | 법령·행정규칙 | 허가(공개 법령) | 예 |
| 국가공무원 복무규칙 PDF(총리령 제2161호, 12쪽) | 법령·행정규칙 | 허가(공개 법령) | 예 |
| 공무원 행동강령 PDF(대통령령 제32661호, 7쪽) | 법령·행정규칙 | 허가(공개 법령) | 예 |
| `data/samples/` 가상 회의록 3개 | 회의록 | 해당 없음 | 아니오 — 회의 기능 전용 |
| `data/external/` 공개 국회 회의록 발췌·라벨 | 회의록 | 해당 없음 | 아니오 — 회의 평가 전용 |
| `data/eval/`, `data/roster.yaml`, `data/regulations/eval/` | QA 예제·가상 자료 | 해당 없음 | 아니오 — 평가 전용 |
| `data/state.db` | 손상·미지원·권한 미확인 | 해당 없음 | 아니오 — 업무 DB |

- 원문은 사용자 폴더에서 읽기만 하고 옮기거나 고치지 않습니다. 시행일은 파일 이름이 아니라 본문 첫머리의 "[시행 …]"에서 읽습니다.
- 각 쪽의 "법제처 n 국가법령정보센터"(n은 인쇄 쪽수로만 씀)와 그 아래 반복되는 법령명은 본문이 아니라서 지웠습니다.
- **제외한 것**
  - 부칙 3건, 머리말(제목·시행 정보·소관 부처 연락처) 3건
  - 삭제 조문 21개, 삭제 항 2개
  - 이미지로 된 표 2개: 복무규정 제15조 재직기간별 연가 일수 표, 제16조 연가 미리 사용 표. OCR하지 않았습니다.
- **별표·별지**: PDF에 들어 있지 않습니다. 조문이 가리키는 별표 1~3, 별지 1~9·12~14는 청크의 참조에 "(미색인)"으로 남겼습니다.
- **zip 자료**: `sources.safe_extract`가 경로 이탈, 절대 경로, 심볼릭 링크, 비정상 압축 비율을 막고 풉니다. 이번 자료에는 zip이 없었습니다.

## 분할과 색인 (manifest 요약)

| 항목 | 값 |
|---|---|
| 색인 버전 | `v20261010T013558` (`data/index/regulations/`, git 제외) |
| 청크 | 151개 — 복무규정 59, 복무규칙 61, 행동강령 31 |
| 문서 입력 추정 토큰 | 53,365 이하(글자 수를 상한으로 쓴 추정, 실측 아님) |
| 임베딩 | `gemini-embedding-001`, 3072차원, 문서 `RETRIEVAL_DOCUMENT`, 질문 `QUESTION_ANSWERING`, L2 정규화(float32) |
| 미색인 문서 | 없음(대상 3개 모두 상한 안) |

- 조 하나가 청크 하나입니다. 추정 1,200을 넘는 조문(복무규정 제19·20조, 행동강령 제2·14조)만 항, 그다음 호 단위로 나눴습니다.
  - 나눈 청크에도 `[법령명] 제n조(제목) 제m항` 머리를 붙입니다.
  - 단서("다만", "단,")는 앞 문장과 떼지 않습니다.
- `text`는 원문 줄 그대로이고, `search_text`·`embed_text`는 줄을 이은 글입니다.
  - 줄바꿈은 띄어쓰기 자리일 수도, 낱말 가운데일 수도 있습니다. 그래서 줄 끝 낱말과 다음 줄 첫 낱말만 형태소 분석기(Kiwi)에 보여 띄울지 정합니다.
  - 개정 표시(<개정 …>, [전문개정 …])는 검색 글에서 뺍니다. 숫자·부정·단서·예외는 바꾸지 않습니다.
- 참조 "제n조", "같은 영 제n조", "「국가공무원 복무규정」 제2조제3항, 제5조…"는 색인된 조문이면 청크 ID로, 아니면 원문 표현으로 남깁니다.
- 위치는 PDF 쪽과 인쇄 쪽수입니다. 인쇄 쪽수는 각 쪽의 "법제처 n"에서 읽었습니다.
- 새 버전은 임시 폴더에 만들어 검사(ID 중복, 청크와 벡터 1:1, 차원, 정규화)를 통과해야 `CURRENT`가 바뀝니다. 실패하면 기존 색인을 그대로 씁니다.
- 임베딩 캐시 키는 (모델, 차원, task_type, 입력 형식, 글 해시)입니다. 같은 자료로 다시 구축하면 임베딩 호출이 0회입니다(확인함). 앱은 색인을 읽기만 합니다.

## 검증이 확인하는 것과 못 하는 것

`src/onboarding_agent/rag/validate.py`. 화면과 보고에는 실제로 실행된 검사만 "확인됨"으로 씁니다.

| 검사 | 확인하는 것 |
|---|---|
| 근거 ID | 모든 근거 ID가 이번 질문에서 실제로 검색·조회된 청크인지 |
| 근거 연결 | answered이면 설명이 1개 이상이고, 설명·조건마다 근거가 있는지 |
| 조문 표기 | 답변의 "제n조(의m)"이 연결된 근거의 조문이거나 근거 원문이 가리키는 조문인지(항은 확인 못 하면 주의) |
| 수치·날짜 | 아라비아 숫자+단위(일·시간·개월·년·원·%·회 등)와 날짜가 연결된 근거 원문에 그대로 있는지. 한글 수사(하루·반나절 등)는 주의 |
| 문서명 | 답변의 법령·규정 이름이 연결된 근거의 문서명이거나 근거 원문에 나오는지 |
| 단서·예외 | 단서·예외가 있는 근거를 조건에서 인용하지 않으면 주의와 "원문의 단서·예외 확인 필요" |

앞의 다섯 가지 중 하나라도 실패하면 실패 목록을 붙여 1회 다시 생성합니다. 또 실패하면 AI 답변 대신 관련 원문 카드만 보여 주고 `escalation_required`로 둡니다.

**확인하지 못하는 것**: 조건과 적용 범위를 의미상 맞게 해석했는지는 자동으로 검증하지 않습니다. 화면에도 이 한계를 표시합니다.

## 평가

- **개발 세트**(`data/regulations/eval/dev.yaml`, 10문항, 에이전트 작성)는 생성 없이 검색 지표만 쟀습니다. 기대 근거가 있는 8문항 기준입니다.

  | 방식 | hit@1 | hit@3 | hit@5 | MRR |
  |---|---|---|---|---|
  | 벡터 | 0.75 | 1.00 | 1.00 | 0.854 |
  | BM25 | 0.62 | 0.88 | 0.88 | 0.729 |
  | RRF 결합 | 0.62 | 0.88 | 0.88 | 0.766 |

  그래서 기본 방식은 벡터로 정했습니다. BM25는 장애 대비로 둡니다. 보류 기준 0.705는 범위 안 질문의 최저 최고점수(0.716)와 범위 밖 질문의 최고점수(0.696)의 가운데입니다. 범위 밖 질문이 2개뿐이라 표본이 작습니다.
- **최종 세트**(`data/regulations/eval/final.yaml`, 10문항)는 **사용자 검수 전 초안이라 공식 수치가 아닙니다**. 1회 실행했습니다.
  - 생성 예산 5회로 5문항을 생성했고, 1문항은 생성 전 보류됐습니다. 4문항은 예산으로 실행하지 않았습니다.
  - 상태 정확도: 생성 4/5, 보류 1/1. 근거 일치(answered 3문항): 3/3.
  - 검사 실패 0, 재생성 0회. 검색 지표(8문항)는 세 방식 모두 hit@1 1.00입니다.
  - 틀린 1문항은 후속 질문 "그럼 그 휴가는 유급인가요?"입니다. 기대는 answered였는데 모델이 돌봄 대상·자녀 수를 되물었습니다(needs_clarification).
- **실제 화면 확인**
  - 새 질문 "연가는 반나절 단위로도 쓸 수 있나요?" → 복무규정 제16조 근거 카드와 함께 답변
  - 도구 모드 "숙직 근무자는 교대로 잠을 잘 수 있나요?" → 모델이 `search_regulations`를 요청하고 앱이 실행한 뒤 `submit_answer`로 끝남. 복무규칙 제14조

## 호출 사용량 (이번 구축 작업)

| 항목 | 사용 / 상한 |
|---|---|
| 문서 임베딩 | 6요청, 추정 53,625토큰 / 12만(추정). 첫 구축 5요청에 장 제목 수정으로 1청크 재임베딩 |
| 질문 임베딩 | 22 / 30 (개발 10, 최종 10, 앱 2) |
| 생성 | 8 / 12 (최종 세트 5, 앱 질문 1, 도구 모드 2, 재생성 0) |

모든 요청은 `data/regulations/usage.jsonl`(git 제외)에 남습니다. 응답에 토큰 수가 오지 않아 토큰은 추정치입니다. 응답 형태는 `tests/fixtures/rag/embed_response_shape.json`(벡터는 앞 3개 값만)에 있습니다.

`RAG_ENFORCE_BUDGET=true`(기본)이면 위 상한을 넘는 호출을 막습니다. 429가 나면 그 종류의 호출을 멈춥니다. 시연처럼 상한 없이 쓰려면 `.env`에 `RAG_ENFORCE_BUDGET=false`를 넣습니다. 사용량은 계속 기록됩니다.

## 법제처 Open API (별도 트랙, 이번에는 실행 안 함)

- `.env`에 `LAW_API_OC`가 없어 API를 부르지 않았습니다. 이번 답변은 모두 로컬 PDF로만 했고, 최신 버전인지 API로 확인하지 않았습니다(로컬 파일이라 최신 여부 미확인).
- 신청: 국가법령정보 공동활용(open.law.go.kr)의 "OPEN API 신청" 메뉴에서 신청합니다. 인증값(OC)은 "API인증키관리" 메뉴에서 관리합니다(문의 02-2109-6446). 받은 값을 `.env`의 `LAW_API_OC`에 넣습니다.
- 공식 활용 안내의 목록 조회 예: `https://www.law.go.kr/DRF/lawSearch.do?OC=<OC>&target=eflaw&query=<법령명>`. 본문은 목록의 법령일련번호나 상세 링크로 조회하고, 응답에 조문·부칙·별표가 들어 있습니다.
- 본문 조회의 정확한 요청 형식과 필드명은 실제 응답을 fixture로 저장해 확인한 뒤 파서를 만듭니다(추측해서 만들지 않음). 원본은 `data/raw/law_api/`(git 제외)에 법령명·시행일자·수집 시각별로 따로 둡니다.
- API로 받으면 이미지로 빠진 연가 일수 표와 별표를 텍스트로 받을 수 있을 것으로 봅니다(미확인).
