# 적용 전(수작업) 측정 절차

README 전/후 비교표의 "적용 전" 값은 사람이 직접 잽니다. 이 문서는 절차와 양식만 둡니다. 결과 수치는 아래 기록 양식으로 따로 모으고, 여기에는 적지 않습니다.

## 준비

- **회의록**: `data/samples/`의 가상 회의록 3개(01 정리형, 02 녹취형, 03 메모형). 측정자는 미리 읽지 않습니다.
- **측정자**: 2명 이상. 회의록 순서는 사람마다 다르게 합니다(익숙해지는 효과를 줄이기 위해).
- **도구**: 평소 쓰는 캘린더, 데모 Slack 워크스페이스, 스톱워치(또는 시각 기록).
- **정답**: `data/eval/meeting_gold.jsonl`의 라벨. 측정이 끝난 뒤 품질 비교에만 씁니다.

## 수작업 단계

각 단계의 시작·끝 시각을 적습니다.

1. **읽기**: 회의록을 처음부터 끝까지 읽습니다.
2. **정리**: 결정사항과 액션 아이템(할 일·담당자·기한)을 표로 적습니다. "다음 주 금요일"처럼 상대 표현은 날짜로 바꿉니다.
3. **캘린더 등록**: 기한이 있는 항목마다 일정을 하나씩 만듭니다. 제목에 할 일과 담당자를, 메모에 근거 문장을 넣습니다.
4. **Slack 공유**: 채널에 요약과 할 일 목록을 한 메시지로 올리고 담당자를 멘션합니다.

## 시간 재는 기준

- **시작**: 회의록 파일을 연 순간. **끝**: Slack 메시지 전송 버튼을 누른 순간.
- 단계 사이 망설이는 시간도 그대로 셉니다(실제 업무와 같게). 전화·자리 비움 같은 외부 중단만 따로 적어 뺍니다.
- 담당자나 기한이 회의록에 없을 때는 평소처럼 처리하고, 어떻게 했는지(추측, 비워 둠, 확인 필요 표시)를 비고에 적습니다.
- 품질도 함께 적습니다: 정답 라벨과 비교해 빠뜨린 항목 수, 잘못 적은 담당자·기한 수.

## 적용 후 측정 (비교용)

- 같은 회의록과 측정자로 앱을 씁니다: 업로드 → 추출 → 검토·수정 → 승인. 시작 기준은 같고, 끝은 승인 버튼을 누른 순간입니다(캘린더·Slack은 앱이 만듦).
- 추출 시간은 `report_metrics.py`의 평균 추출 지연으로, 검토·수정 시간은 사람이 잽니다.
- 측정 중 생긴 이벤트만 모으려면 `uv run python scripts/report_metrics.py --since <측정 시작 시각> --until <끝 시각>`을 씁니다.
- 앱 결과의 품질(미확정 비율, 사람이 고친 셀 비율)도 같은 출력에서 옮겨 적습니다.
