# 신입사원 온보딩 AI Agent

신규 임용 공무원(국가데이터처(구 통계청) 및 소속기관)의 반복 질문과 회의 후속 업무를 AI Agent가 대신 처리해, 인사담당자의 수작업을 줄이는 업무용 Agent입니다.

> Seoul National University KDT 13기 팀 프로젝트 (Category C: 업무용 AI Agent)
> 과제물 제출 10/13 · 최종 발표 10/15

## 해결하려는 문제

- 신입은 입사 후 한 달간 연가·복리후생·조직·비품 같은 비슷한 질문을 반복하고, 인사담당자가 매번 수작업으로 응대합니다.
- 복무규정 같은 법령 원문은 문어체라 신입이 직접 읽고 이해하기 어렵습니다.
- 회의 후 결정사항 정리, 담당자·기한 지정, 일정 등록, 공유가 모두 수작업이라 누락이 생기기 쉽습니다.

## 핵심 기능

### 1. 규정 기반 질의응답 (RAG + LLM)
- 신입이 채팅으로 질문하면 규정·법령에서 근거 조문을 찾아 **조문 번호와 함께 쉬운 말로 풀어서** 답합니다.
- 근거를 찾지 못하거나 확신이 낮으면 추측하지 않고 "담당자에게 물어볼게요"로 에스컬레이션합니다.
- 지식 소스: 법제처 국가법령정보센터 Open API(국가공무원 복무규정 등), 공개 규정집·복리후생 안내 문서

### 2. 회의록 → 액션 자동화
- 회의 텍스트 파일을 올리면 요약하고 **결정사항·담당자·기한**을 추출합니다.
- 사용자가 내용을 확인·수정해 승인하면 Google Calendar에 일정을 등록하고 Slack으로 담당자에게 알립니다.
- 담당자나 기한이 회의록에 없으면 추측하지 않고 "미확정"으로 표시해 사용자가 채웁니다.
- 기한 전 미완료 항목은 배치 스케줄러가 재알림합니다.

## 아키텍처

```
사용자 ↔ Streamlit 웹앱 ↔ Agent (OpenAI function calling)
                              ├─ 법령·규정 검색 (RAG, 법제처 Open API)
                              ├─ Google Calendar (일정 등록)
                              └─ Slack (알림)
배치 스케줄러 (GitHub Actions) ↔ 상태 저장소 ← Agent  → 기한 전 재알림
```

| 구성 | 기술 |
|---|---|
| UI / 서버 | React + Vite / FastAPI |
| LLM | OpenAI (function calling), 장애 시 모델 자동 전환 + 규칙 기반 폴백 |
| 검색 | OpenAI 임베딩 + 키워드 하이브리드 검색 (조·항·별표·예규 PDF 쪽 단위 약 6,000청크) + 질의 확장 + LLM 재순위 |
| 법령 데이터 | 법제처 국가법령정보센터 Open API |
| 일정 / 알림 | Google Calendar API / Slack API |
| 상태 저장소 | 경량 DB(SQLite) 또는 Google Sheets |
| 배치 | GitHub Actions |

## AI 적용 전/후

| 업무 | 적용 전 | 적용 후 |
|---|---|---|
| 규정 질문 응대 | 인사담당자에게 문의 후 대기 | 채팅에서 즉시 답변, 조문 번호 인용 |
| 법령 해석 | 원문을 직접 찾아 읽음 | 쉬운 요약 + 근거 조문 |
| 회의 후 정리 | 사람이 회의록을 읽고 정리 | 파일 업로드 후 자동 요약·추출 |
| 일정 등록·알림 | 캘린더·메신저에 수작업 | 승인 시 자동 등록·발송, 기한 전 재알림 |

소요시간 등 실측값은 시연 후 채울 예정입니다.

## 리스크와 대응

- **LLM 환각** → 근거 문서만 사용하도록 제한, 근거 부족 시 담당자 에스컬레이션
- **회의록 추출 오류** → 미확정 표시, 등록 전 사용자 확인·수정
- **LLM API 장애·한도 소진** → 모델 자동 전환, 규칙 기반 폴백
- **업무 데이터의 외부 LLM 전송** → 데모는 공개·가상 데이터만 사용
- **실제 그룹웨어 연동 불가** → 범위에서 제외하고, 실제 연동 가능한 Google Calendar·Slack으로 액션 구현

## 개발 현황

| 기능 | 상태 |
|---|---|
| 규정 질의응답 (RAG) | 구현 완료. 복무·여비·보수·수당·후생복지·국가공무원법·임용령·행동강령·국가데이터처 직제·맞춤형 복지제도 운영지침에 더해 청탁금지법·공무원연금법·재해보상법·인재개발법·성과평가·통계법·소득세법(연말정산)·조세특례제한법, 인사혁신처 예규 2종(보수 업무지침, 복무·징계 예규) 색인, 조문 번호 인용, 업무 범위 밖 질문은 안내, 근거 없는 업무 질문은 에스컬레이션 |
| 회의록 → 요약·결정사항·액션 아이템 추출 (기능 2) | 웹앱에 **임시 버전** 포함. 팀원이 구현 중인 기능 2(근거 인용 검증, 담당자 규칙, 캘린더·리마인더 등, PR #1)가 완성되면 필요한 부분을 웹앱에 통합 예정 |
| Slack 알림 | 임시 버전: `SLACK_WEBHOOK_URL` 설정 시 실제 발송, 없으면 미리보기. 팀원 구현본 통합 시 교체 |
| 일정 등록 | 임시 버전: .ics 파일 생성. Google Calendar API 연동은 기능 2 통합 때 반영 |
| 기한 전 재알림 배치 | 예정 |

검색 정확도는 `python -m tests.rag_eval`로 재현할 수 있습니다 (질문 68개 기준 재순위 포함 hit@3 85%, hit@5 90%).

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env                    # OPENAI_API_KEY, LAW_API_OC 입력
.venv/bin/python -m backend.rag.build   # 인덱스 재생성 (저장소에 포함돼 있어 생략 가능, 첨부 PDF 변환에는 poppler의 pdftotext 필요)
cd web && npm install && npm run build && cd ..
.venv/bin/uvicorn backend.api:app --port 8000   # http://localhost:8000
```

프론트 개발 중에는 위 서버와 `cd web && npm run dev`(5173)를 함께 실행합니다. 테스트는 `python -m pytest`.

## 배포 (Render)

`render.yaml`과 `Dockerfile`이 포함돼 있습니다. Render에서 **New → Blueprint**로 이 저장소를 연결하고 환경변수 `OPENAI_API_KEY`, `ACCESS_CODE`(접근 코드), 선택으로 `SLACK_WEBHOOK_URL`을 입력합니다. 공개 URL이므로 `ACCESS_CODE`는 반드시 설정하세요. 무료 플랜은 15분간 요청이 없으면 잠들어 첫 접속이 느립니다.
